# Gate 9: minimal MMPD engineering path

This is an evaluation-only structural implementation. The canonical scientific plan remains 15 subjects, 300 clips, and its sealed rules. The checked-in engineering manifest excludes `p29_3`, contains 299 clips, ten primary arms, 53 hops per clip, and 158,470 primary rows. It is explicitly not a scientific result.

The real callable path is `adaptive_roi_rppg.evaluation.adapters.mmpd.production:extract_gate9`, loaded by `scripts/evaluate_mmpd_gate9.py`. It resolves each authenticated inventory locator below `--raw-root`, calls `extract_mmpd_measurements` for MediaPipe ROI RGB -> causal POS/HR, loads the ten frozen identities (full-face action 0 plus nine SB3 recurrent policies), replays without GT, then runs MMPD-local Oracle B/C and emits canonical rows. The corrected-GT rule is repository-owned as `mmpd_causal_periodogram_peak_v1` in `mmpd/rules.py`; preflight requires the manifest hash and bytes to match that exact source. The path is sealed cohort -> authenticated regular MAT/video source -> causal ROI RGB extraction -> causal POS/HR -> frozen-policy replay -> Oracle B/C diagnostics -> canonical `per_hop.csv` -> row-rebuilt clip and subject summaries -> `COMPLETE.json` last. No MMPD data is used for training, tuning, reward design, feature design, calibration, or checkpoint selection.

The publication boundary rejects symlinks, changed source bytes, unknown clips, duplicate method/clip/hop keys, missing validity reasons, GT observations, non-causal resets, and incomplete lattices. A run starts with exclusive `STARTED.json`; caught pre-completion failures write `FAILED.json`; only a fully validated artifact inventory can write `COMPLETE.json`.

Production preflight requires an authenticated 299-entry raw-source inventory whose relative locators resolve to regular non-symlink files with matching byte sizes and SHA-256 values; an authenticated metadata JSON containing all 299 `clip_id`/`subject_id`/`view`/`condition` records; the repository-owned frozen MMPD corrected-GT rule identity; the exact ten method-to-family/seed/kind checkpoint identities; the extraction/POS/controller/replay/SB3 source closure; an authenticated MediaPipe face-landmarker model passed as `--face-landmarker-model` with `--face-landmarker-model-sha256`; and the sealed effective plan hash. The current face-relative rectangles are `engineering_face_relative_rectangles_v1`, not the approved semantic trained ROI mapping, so checkpoint results are explicitly `engineering_only_unverified_roi_mapping` and cannot support a frozen-policy claim. Gate 9 replay is implemented locally so it initializes `mmpd` controller state and never calls the MCD replay ruler. The implementation does not run full MMPD extraction, Slurm jobs, or scientific corrected-GT/metadata rules in this checkout. These prerequisites remain remote-only until their actual files and hashes are sealed. No artifact from this engineering path is a scientific result.
